# Routage

## Convention actuelle

Le projet n'utilise **pas** de routes URL pour les sections internes. La navigation se fait via un état React (`activeId`) dans `Dashboard.tsx`, contrôlé par `sections.ts`.

```
Route "/*" → DashboardPage → Dashboard
                               └── état activeId → SectionView | ResetPanel | ImportPanel | ElementsPanel
```

## Ajout de la section Éléments

La route reste `/` (dashboard). La section "Éléments" apparaît dans la nav latérale selon le rôle.

Roles qui voient la section :
- **Super-Admin, Admin, Supervisor** : ajouté après RESET
- **Technicien, Observateur, autres central** : ajouté après COMPUTERS (section la plus pertinente pour le terrain)

Protection d'accès : déjà assurée par `sectionsForRole()` côté client et par les droits GLPI côté API.

```typescript
// sections.ts
const ELEMENTS: Section = {
  id: 'elements',
  label: 'Éléments',
  icon: '📦',
  endpoint: '',
  columns: [],
  custom: 'elements',
}
```

# Recherche multicritère

## Formulaire : `ElementsFilters.tsx`

| Champ | Type UI | Filtre |
|-------|---------|--------|
| Name | `<input type="text">` | Serveur (RSQL `name=ilike=*…*`) |
| Status | `<input type="text">` | Client (nom du statut) |
| Location | `<input type="text">` | Client (nom de la localisation) |
| Manufacturer | `<input type="text">` | Client (nom du fabricant) |
| Item_Type | `<select>` | Serveur (choix de l'endpoint) |
| Model | `<input type="text">` | Client (nom du modèle) |
| Inventory_Number | `<input type="text">` | Client (numéro inventaire) |
| User | `<input type="text">` | Client (nom utilisateur) |

Combinaison : les filtres sont appliqués en AND (tous doivent correspondre).

Boutons :
- **Rechercher** — applique les filtres, déclenche fetch
- **Réinitialiser** — vide tous les champs, revient à l'état initial

# Intégration API

## Services réutilisés

| Service | Fonction | Usage |
|---------|----------|-------|
| `apiClient.ts` | `apiFetch()` | Indirectement via fetchList |
| `glpiApi.ts` | `fetchList(path, {start, limit, filter})` | Fetch paginé par endpoint |
| `glpiApi.ts` | `refName(value)` | Normalise `{id,name}` ou valeur brute |

## Nouveau service : `elementsApi.ts`

Fonctions :

```typescript
fetchElements(filters: ElementFilters): Promise<ElementRow[]>
```

Comportement :
1. Détermine la liste des types à interroger (tous si `itemType` vide)
2. Lance les fetches en parallèle (`Promise.allSettled`)
3. Ignore les endpoints en erreur (type non supporté par l'instance GLPI)
4. Normalise chaque ligne via `normalizeRow(raw, itemType)`
5. Retourne la liste fusionnée

Filtre RSQL côté serveur : `name=ilike=*valeur*` si `filters.name` renseigné.
Filtres restants : appliqués côté client pour éviter les incompatibilités entre endpoints.

Limite par endpoint : 200 items (ajustable). Affiche un bandeau si résultats tronqués.
